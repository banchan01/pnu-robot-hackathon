# 소방 구조 로봇 지휘 콘솔 (web/)

TurtleBot3 구조 로봇을 **소방관 대신 화재 현장에 진입하는 무인 구조 로봇**으로 설정하고,
지휘관이 웹 브라우저에서 로봇의 상태를 실시간으로 확인하며 출동 모드와 목표를 바꾸는 콘솔이다.

## 실행 방법

추가 라이브러리는 필요 없다. Python 표준 라이브러리만 사용한다.

```bash
# 1) Webots에서 worlds/apartment_mission.wbt 를 열고 실행한다 (컨트롤러: tb3_mission)
# 2) 저장소 루트에서 콘솔 서버를 띄운다
python web/server.py                # 기본 http://127.0.0.1:8000/
python web/server.py --port 8080    # 포트 변경
# 3) 브라우저에서 위 주소를 연다
```

같은 네트워크의 다른 기기(태블릿 등)에서 열려면 `--host 0.0.0.0` 을 준다.

## 화면 구성

화면은 세 열로 나뉜다.

| 위치 | 내용 |
|---|---|
| 왼쪽 | 로봇이 만들어 가는 점유 격자 지도(경로, 궤적, frontier, 로봇 자세 포함)와 **탐지 표식 마커**, 표식 목록, 상태 타일(남은 요구조자, 구조 수, 탐색률, 이동 거리, 전방 장애물 거리, 금지 표식 수), 제한 시간 진행 막대, 탐색률 추이 그래프, 최근 60초 속도 명령 그래프 |
| 중앙 | 큰 영상 화면. 상단 탭으로 **로봇 시점**(전방 카메라와 탐지 결과), **상공 시점**(로봇을 따라다니는 천장 카메라), **지도 확대**(지도와 클릭 가능한 마커)를 전환한다. 아래에는 **자동 임무 / 수동 조종** 전환과 방향 패드, 속도 슬라이더가 있고, 그 아래에 Behavior Tree 실행 상태가 보인다. |
| 오른쪽 | 출동 모드 버튼, 직접 지휘(정지, 재개, 즉시 복귀, 표식 색과 인원 변경, 자유 텍스트 명령), 구조 기록, 현장 로그 |

### 탐지 표식 마커

컨트롤러가 카메라로 검출한 표식은 색과 위치로 묶여 객체 등록부에 쌓이고, 지도 위에 색상 원으로 표시된다.
마커나 목록 항목을 클릭하면 객체 번호, 색과 의미, 지도 좌표(m), 관측 횟수, 최초와 최근 관측 시각이 뜬다.
접근 중인 목표는 깜빡이고, 구조가 끝난 표식에는 체크가 붙으며, 금지 표식은 점선 테두리로 구분된다.
지도의 빈 곳을 클릭하면 그 지점의 좌표가 잠시 표시된다.

### 자동 임무 / 수동 조종

처음에는 자동 임무 상태로 Behavior Tree가 스스로 탐색과 구조를 진행한다.
**수동 조종** 버튼을 누르면 컨트롤러에 `manual` 명령이 가고, 브라우저가 0.1초마다 속도(v, w)를 `manual.json`에 보낸다.
키보드 W A S D 또는 방향키, 화면의 방향 패드(터치 가능), 속도 슬라이더로 조종하며, 스페이스나 가운데 버튼은 정지다.
컨트롤러는 0.7초 넘게 새 속도가 오지 않으면 스스로 정지하므로(데드맨), 브라우저를 닫거나 네트워크가 끊겨도 로봇이 폭주하지 않는다.
수동 조종 중에도 LiDAR 기반 전방 정지와 감속은 그대로 적용되고, 지도 갱신과 표식 탐지도 계속된다.
**자동 임무** 버튼을 누르면 `auto` 명령으로 Behavior Tree가 이어서 임무를 진행한다.

### 상공 시점 (천장 카메라)

`worlds/apartment_mission.wbt`와 `apartment_debug.wbt`에는 `overhead_cam`이라는 Supervisor Robot 노드가 추가되어 있다.
이 노드는 물리 없이 TurtleBot3 위 2.2 m를 따라다니며 아래를 내려다보고, 화면 위쪽이 로봇 진행 방향이 되도록 회전한다.
프레임은 `controllers/overhead_cam/overhead_cam.py`가 `output/live_top.jpg`로 저장한다.
이 노드가 없는 월드에서도 미션 컨트롤러와 콘솔은 정상 동작하며, 상공 시점 탭만 비활성화된다.

## 출동 모드 (시나리오)

아파트 화재가 발생했고 연기 때문에 소방관이 바로 진입할 수 없는 상황을 가정한다.
로봇이 먼저 진입해 요구조자를 찾고 위치를 보고한 뒤 진입 지점으로 돌아온다.
색상 표식은 현장 상황을 뜻한다. **빨강은 요구조자**, 주황은 가스통 같은 위험물, 초록과 보라는 접근하면 안 되는 구역이다.

| 모드 | 상황 | 로봇 동작 (내부 명령) |
|---|---|---|
| 요구조자 수색 | 기본 임무 | 빨강 2명 수색 후 복귀 (`target red 2`, `resume`) |
| 신속 구조 | 연기가 짙어져 시간이 부족함 | 가장 가까운 1명만 확인 후 복귀 (`target red 1`, `resume`) |
| 위험물 확인 | 폭발 위험 여부를 먼저 알아야 함 | 주황 표식 위치 확인 후 보고 (`target orange 1`, `resume`) |
| 현 위치 대기 | 지휘관이 판단하는 동안 | 제자리 정지, 지도 갱신은 계속 (`stop`) |
| 긴급 철수 | 화재 확산, 붕괴 위험 | 임무 중단 후 진입 지점으로 즉시 복귀 (`return`) |

모드는 `web/modes.json`에 데이터로만 정의되어 있다. 항목을 추가하면 서버를 재시작하지 않아도
버튼이 바로 생기므로, 새로운 시나리오(예: 층별 수색, 특정 구역 우선)는 코드 수정 없이 늘릴 수 있다.

## 동작 원리와 확장성

컨트롤러와 콘솔은 파일 두 개로만 연결된다. 그래서 컨트롤러 본체를 고치지 않고도 지휘 수단을 바꿀 수 있다.

```
브라우저 ──HTTP──> web/server.py ──commands.txt, manual.json──> controllers/tb3_mission (commands.py 가 읽음)
브라우저 <──HTTP── web/server.py <──output/status.json, live_map.png, live_cam.jpg── (bridge.py 가 기록)
                                  <──output/live_top.jpg── controllers/overhead_cam (천장 카메라)
```

- `controllers/tb3_mission/bridge.py`: 매 4 tick마다 상태 JSON을, 16 tick마다 지도와 카메라 이미지를 임시 파일에 쓴 뒤 교체한다. 웹이 절반만 쓰인 파일을 읽는 일이 없고, 콘솔 오류가 미션을 멈추지 않는다.
- `web/server.py`: 명령을 큐에 쌓고, 컨트롤러가 이전 명령을 읽어 파일을 비운 뒤에만 다음 한 줄을 넘긴다. 모드 한 개가 명령 여러 개로 풀려도 순서가 보장된다. 수동 조종 속도는 별도 파일 `manual.json`으로 보낸다.
- `controllers/tb3_mission/commands.py`: `manual`, `auto` 명령과 `manual_cmd()`(속도 파일 읽기, 데드맨)를 담당한다. `bt_mission.py`의 SafetyGate 첫 노드 `ManualOverride`가 수동 상태일 때 속도를 안전 계층을 거쳐 바퀴에 보낸다.
- 명령 채널이 텍스트 한 줄이므로, 같은 방식으로 음성 인식 결과나 무전기 문자, 다른 로봇의 보고를 붙일 수 있다.
- 상태 채널이 JSON이므로, 여러 로봇을 동시에 띄우면 서버 하나가 로봇별 폴더를 읽어 지휘소 화면 하나로 모을 수 있다.

## 현실 적용 시 고려 사항

- 실제 현장에서는 Wi-Fi가 끊길 수 있으므로, 콘솔 연결이 끊겨도 로봇은 제한 시간의 70%가 지나면 스스로 복귀한다(컨트롤러 `return_at_ratio`).
- 상태 파일에는 로봇이 목격한 금지 표식 좌표도 남으므로, 소방관 진입 전에 위험물 위치를 먼저 공유할 수 있다.
- 열화상 카메라나 연기 센서를 붙이면 "요구조자 확정" 조건을 색상 대신 체온이나 연기 농도로 바꿀 수 있고, 이 경우에도 Behavior Tree의 조건 노드 하나만 교체하면 된다.
